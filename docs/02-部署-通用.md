# 部署（通用）：把 OpenWrt 侧装到任意 OpenWrt 路由器

> 本文只讲**通用 OpenWrt 设备**的部署路径。本机（Redmi AX3000 / ipq50xx / QSDK 供应商内核）因为要自编
> 内核模块，另有专门一篇，见文末第 11 节与开头的对应指引。
> 本机自编内核模块（macvlan、NFQUEUE）的全部内容见 `docs/03-部署-AX3000-自编内核模块.md`，
> 本文不展开——本文假设你的设备**不需要**自编内核模块。

## 本文适合谁 / 不适合谁

| | 说明 |
| --- | --- |
| **适合** | 手上是**别的一台 OpenWrt 路由器**（不同架构、不同固件版本），想让校园网 PPPoE 出口在质量差时自动重拨；可选做多拨连接池；可选做 SNI 分流。设备能装官方 feed 或自编的 `kmod-macvlan`，不需要你碰内核编译。 |
| **不适合** | ① 想在这台 Redmi AX3000 上复现（要自编 `kmod-macvlan` / `xt_NFQUEUE`）→ 看 `docs/03-部署-AX3000-自编内核模块.md`；② 使用 OpenWrt 22.03 及以上的 **fw4/nftables** 固件做 SNI 分流 → 走 zapret 上游 `install_easy.sh`（见第 7 节）；③ 期望本仓库提供绕过认证的能力（见下）。 |

**项目声明（一贯立场，`INSTALL.md` 同款）**：本仓库**不实现**绕过认证、伪造凭据、修改白名单、
破解计费或访问控制等功能。它只做一件事：用你**自己的合法账号**做 PPPoE 拨号，探测出口是否达标，
不达标就重拨。探针与测速端点默认值是示例地址，正式部署必须换成你自己学校/运营商**明确可达或授权**的端点。

OpenWrt 侧代码本次重组后**全部**位于 `CampusRedialWrt/` 下；仓库根的 C#/.NET 与 PowerShell 属于 Windows 侧，
与本文无关。

## 1. 部署总览：要装什么、装在哪、前置条件

OpenWrt 侧是一个**主件 + 两个可选件**的结构，三块互相独立，可以只装第一块。

| # | 组件 | 仓库位置 | 装到路由器哪里 | 是否必需 | 关键前置条件 |
| --- | --- | --- | --- | --- | --- |
| 1 | LuCI 应用（`campus-rediald` 守护进程 + `campus-redialctl` + rpcd 插件 + 前端页面） | `CampusRedialWrt/luci-app-campus-redial/` | 由 `.ipk` 装到 `/etc/config`、`/etc/init.d`、`/usr/sbin`、`/usr/libexec/rpcd`、`/www/luci-static` | **必需** | 21.02.x（opkg/fw3）；已存在协议为 `pppoe` 的 `wan` 接口 |
| 2 | mwan3 多拨连接池 | 同上（由守护进程生成 `mwan3` 段） | `/etc/config/mwan3` 中 `campus_redial_*` 段 | 可选（`pool_size > 1` 才有意义） | `mwan3` 包 + 与内核**严格匹配**的 `kmod-macvlan` |
| 3 | SNI 分流（zapret） | `CampusRedialWrt/tools/install-sni-desync.sh` | `/opt/zapret`、`/etc/init.d/zapret`、`/etc/firewall.zapret`、`/etc/hotplug.d/iface/90-zapret` | 可选 | OpenWrt 21.02.x（fw3/iptables）；`armv7` 二进制开箱可用 |

组件 1 与 3 之间只有一处耦合：LuCI 页面会显示 SNI 分流状态并提供 hostlist 编辑与启动/停止按钮
（走 `campus_redial` 的 `zapret_status` / `zapret_hostlist_get` / `zapret_hostlist_set` / `zapret_service`）。
没装 zapret 时页面显示“未安装”，不影响主功能。

## 2. 前置条件与支持范围

| 项目 | 要求 | 依据 |
| --- | --- | --- |
| 固件 | **OpenWrt 21.02.7**（opkg / fw3 / iptables） | 21.02.7 为当前验收目标；标准 Lua rpcd 插件，不依赖 ucode |
| 架构 | release 里提供 **`luci-app-campus-redial_1.0.0-2_all.ipk`（`Architecture: all`）**，任意 21.02.x 设备可直接安装；只有想要 `campus-redial-bind.so` 时才需要按第 3 节自行构建 | 通用包不含架构相关二进制（见下），已用真机 `opkg install --noaction` 验证依赖全部可解析 |
| 构建环境 | 需要一个 **Linux 环境**做 SDK 构建（WSL / Docker / 虚拟机均可）；Windows 原生不可用 | 仓库的构建验证在临时 Ubuntu glibc rootfs 中完成 |
| 主件依赖 | 通用包的依赖：`libc`、`luci-base`、`rpcd`、`rpcd-mod-luci`、`uclient-fetch`、`curl`、`ca-bundle`、`ppp`、`ppp-mod-pppoe`、`ip`（虚拟包，`ip-tiny`/`ip-full` 均可）、`jsonfilter`；多拨另需 `kmod-macvlan`、`mwan3` | 见 release notes；`Makefile` 的 `DEPENDS` 里那套是 SDK 构建用的（含 `kmod-macvlan`/`mwan3` 硬依赖） |
| 网络形态 | 目标接口必须是 **PPPoE**；本包只操作 `wan` 及自己创建的 `wan2..`，不碰 LAN/Wi-Fi/uhttpd/LuCI | 守护进程启动前校验，设备是 LAN 或桥接会直接拒绝 |
| SNI 分流（可选） | 21.02.x 的 **fw3/iptables** 路径；22.03+ 的 fw4/nftables 本仓库脚本会**拒绝执行**并提示走上游 | `CampusRedialWrt/tools/install-sni-desync.sh` 的 `check_requirements` |
| SNI 分流架构（可选） | 内嵌发行包默认只取 `binaries/linux-arm`（armv7）；mipsel/mips/x86_64/aarch64 需改脚本顶部路径与四个 SHA-256 | 见 `docs/reference/SNI-DESYNC.md` 第四节 |

**哪些是实测验收过的、哪些要自行构建**：

- 实测验收过：21.02.7 上的前端/RPC/脚本部署验收（rpcd 注册 `status/start/stop/test/redial_once/clear_stats/logs`，
  LuCI/uhttpd 正常监听，脚本 `sh -n` 全通过）；空凭据时明确记录“PPPoE 用户名为空”且不会把 DHCP 的 `wan`
  改写成 PPPoE；`/etc/config/campus-redial` 保持 `0600`。
- **现成的通用包**：release 附带 `luci-app-campus-redial_1.0.0-2_all.ipk`（`Architecture: all`），
  已在真机上用 `opkg install --noaction` 空跑验证（依赖全部解析、零错误），包内容与实机运行中的部署
  逐文件比对一致。直接装它即可，不必自己构建。
- 需要自行构建的情况：想要 `campus-redial-bind.so`（架构相关的 LD_PRELOAD 绑定库）时按第 3 节走 SDK；
  通用包**不含**它，改用 `curl --interface <会话>` 做每会话绑定（因此通用包把 `curl` 列为硬依赖）。
- 验收边界（务必按此预期部署）：**多拨连接池的真实环境/分流运行时验收尚未完成**。已实测的是 VM 里的
  `pool_size=2/5` 收敛、60 秒认证间隔、独立 MAC、测速互斥；**未闭合**的是掉线自动补拨、mwan3 实际分流
  叠加效果（iperf3 总吞吐 > 单会话）、`busy_threshold_kbytes` 大流量挂起。

## 3. 构建 LuCI 应用安装包（21.02.7 标准 SDK）

【在 Linux 构建机（WSL / Docker / 虚拟机）执行】

1. 从 <https://downloads.openwrt.org/releases/21.02.7/targets/> 下载与路由器 **target 完全对应**的
   21.02.7 SDK（例如 x86/64 用 `openwrt-sdk-21.02.7-x86-64_gcc-*.Linux-x86_64.tar.xz`）。

2. 把包源码放进 SDK 并编译：

   ```sh
   tar -xf openwrt-sdk-21.02.7-*.tar.* -C /opt && cd /opt/openwrt-sdk-21.02.7-*
   mkdir -p package/luci-app-campus-redial
   # 方式 A：直接拷贝仓库目录（推荐，内容始终与仓库一致）
   cp -a /path/to/campus-network-redial/CampusRedialWrt/luci-app-campus-redial package/
   # 方式 B：用 release 里附的源码归档
   # tar -xf /path/to/luci-app-campus-redial-1.0.0-src.tar.gz -C package/
   make defconfig
   make package/luci-app-campus-redial/compile V=s
   ```

3. 定位产物：

   ```sh
   find bin/packages -name 'luci-app-campus-redial*.ipk'
   ```

**为什么必须用同版本 SDK**：`.ipk` 的依赖里包含 `kmod-macvlan` 这类内核模块包，它们在 OpenWrt 中按
内核版本/ABI 索引。用别的版本 SDK 构建的包，装到 21.02.7 上会出现内核模块依赖无法满足
（`kernel version mismatch` 一类错误），而不是装不上主程序。SDK 版本与固件版本**严格一致**是硬要求。

## 4. 安装与首次验证

### 4.1 把包传到路由器

【在 Windows / Linux 工作机执行】

任选其一：

```sh
# scp 可用时
scp luci-app-campus-redial_*.ipk root@<路由器IP>:/tmp/

# 路由器只接受一次性 SSH 密码会话（无 scp/sftp）时，用标准输入管道
ssh root@<路由器IP> 'cat > /tmp/luci-app-campus-redial.ipk' < luci-app-campus-redial_*.ipk
```

### 4.2 安装

【在路由器执行】

```sh
opkg update                                    # 让 kmod-macvlan、mwan3 等依赖可解析
opkg install /tmp/luci-app-campus-redial.ipk
/etc/init.d/rpcd restart
/etc/init.d/uhttpd restart
```

安装后 postinst 会自动 `chmod 600 /etc/config/campus-redial`，并执行
`/etc/init.d/campus-redial enable`（procd 开机自启）。

### 4.3 验证

【在路由器执行】

```sh
opkg list-installed | grep campus-redial      # 包已登记
/etc/init.d/campus-redial enabled && echo OK  # 自启动链接存在
ls /etc/rc.d/S*campus-redial
ubus call campus_redial status                # RPC 可用；未配置时为空闲/不可用状态
```

浏览器打开 LuCI，左侧 **服务 → 校园网自动重拨和集流**（即 `admin/services/campus-redial`）。
看不到菜单时：确认 `/usr/share/luci/menu.d/luci-app-campus-redial.json` 存在，重启 `rpcd`/`uhttpd`，
再清浏览器缓存。

### 4.4 常用运维命令（速查）

【在路由器执行】

```sh
/etc/init.d/campus-redial status|start|stop|enable|disable
/usr/sbin/campus-redialctl start          # 启动自动重拨状态机
/usr/sbin/campus-redialctl stop           # 取消当前任务（等待/探测/测速/拨号一起取消）
/usr/sbin/campus-redialctl test           # 只测当前在线出口，不拨号
/usr/sbin/campus-redialctl redial_once    # 立即断开重拨一轮并测试
/usr/sbin/campus-redialctl clear_stats    # 清空累计统计
ubus call campus_redial status
ubus call campus_redial logs '{"lines":100}'   # 读最近日志（脱敏）
```

| 路径 | 内容 |
| --- | --- |
| `/var/run/campus-redial/status.json` | 当前状态（含 `sessions` 数组、各模式结果、速度、计数） |
| `/var/run/campus-redial/session.<name>` | 每条会话的 key=value 状态 |
| `/var/log/campus-redial.log` | 应用日志（0600，超过 128 KB 自动截断保留 400 行） |
| `/etc/config/campus-redial` | UCI 配置（0600，含账号密码） |
| `/etc/campus-redial/stats.json`、`last-run.json` | 累计统计、最近一次任务结果（含真实测速值） |

守护进程 stdout/stderr 由 procd 接管，`logread | grep -i campus` 也能看到。

## 5. 初始配置

### 5.1 先决条件：必须先有一个 PPPoE 类型的 wan 接口

本包**不会替你创建** `wan`。先到 **网络 → 接口** 确认存在一个协议为 **PPPoE** 的 `wan`，并选好物理设备
（如 `eth1`）。守护进程启动时会拒绝：不存在的接口、协议不是 PPPoE 的接口、以及任何 LAN/桥接设备。
空凭据时它只会记录“PPPoE 用户名为空”，**不会**把 DHCP 的 `wan` 改写成 PPPoE。

### 5.2 LuCI 页面逐项怎么填（推荐）

打开 **服务 → 校园网自动重拨和集流**：

| 配置项 | 默认值 | 怎么填 |
| --- | --- | --- |
| PPPoE 账号 / 密码 | 空 | 校园网拨号账号密码；密码只写入 `/etc/config/campus-redial`（0600），不会出现在状态 RPC 或日志中 |
| WAN 接口 | `wan` | 目标 PPPoE 接口名 |
| WAN 物理设备 | 空 | 留空时自动读 `network.wan.device` |
| 普通模式 / 200 Mbps 模式 | 都开 | 两个都开时**都通过**才算好出口 |
| 测速地址 `bandwidth_test_uri` | 西电测速端点 | **其他学校必须换成自己可达的测速地址** |
| 探针地址 `probe_uri` | 斗鱼 CDN 示例地址 | 换成本校/运营商明确授权的健康检查地址更稳 |
| 测速阈值 `bandwidth_threshold_mbps` | `150` | 按本校实际带宽调整 |
| 连接池大小 `pool_size` | `1` | 单会话最稳；多拨再调大（见第 6 节） |
| 认证间隔 `auth_interval_seconds` | `60` | 多拨务必 60（见第 6 节） |
| 大流量挂起阈值 `busy_threshold_kbytes` | `0` | 会话出口秒级流量超过该值就推迟检测；`0` 关闭该保护 |
| 最大尝试次数 `max_attempts` | `99` | 达到上限后停在失败态，不再无限重拨 |

保存后点 **启动自动重拨**；页面每 2 秒轮询一次状态。

### 5.3 命令行方式（无 LuCI 时）

【在路由器执行】

```sh
uci set campus-redial.main.pppoe_username='<账号>'
uci set campus-redial.main.pppoe_password='<密码>'
uci set campus-redial.main.pool_size='1'               # 多拨再调大
uci set campus-redial.main.auth_interval_seconds='60'  # 多拨务必 60
uci set campus-redial.main.enabled='1'
uci commit campus-redial
chmod 600 /etc/config/campus-redial
/etc/init.d/campus-redial restart
```

命令行写密码会留在 shell history 里；能进 LuCI 就尽量用页面填。

### 5.4 多账号

`/etc/config/campus-redial` 支持 `config account` 段（`label` / `username` / `password` /
`max_connections` / `enabled`）。当**至少一个 enabled 账号填了用户名密码**时，所有启用账号的
`max_connections` 之和就是连接池大小，主配置里的 `pppoe_username` / `pppoe_password` 被忽略。
同一账号也可以拆成多个条目（例如两个相同凭据、各 `max_connections=2`，期望池为 4 条会话）。
状态与页面只返回条目 ID/显示名称，不返回密码。

## 6. 可选：多拨连接池

**目标**：同一账号开多条 PPPoE 会话，交给 mwan3 按连接分流，让单机总吞吐超过单会话。

【在路由器执行】

```sh
opkg update
opkg install mwan3 kmod-macvlan        # kmod-macvlan 必须与内核版本一致，走官方源
lsmod | grep macvlan                   # 确认模块已加载
```

配置要点：

- `pool_size > 1` 时，守护进程为第 2 条起的会话创建**自己的** `campus_wanN_device` 段，下层设备是短名
  `crwanN` 的 **macvlan**，每条会话**独立 MAC** 和独立 `pppname`。（独立 MAC 是实测结论：早期用 802.1Q
  VLAN 无法通过 BRAS；名称必须落在 Linux 15 字符限制内，否则 netifd 会出问题。）
- **认证间隔必须给足**：实测同一账号的认证频率过密会被 BRAS 拒绝——5 秒间隔的五会话实测只能收敛
  **2/5**，改成 **60 秒**后按 `wan→wan2→…` 错峰拨号收敛到 **5/5**（五条分别测速约
  182.98/365.04/185.73/374.73/384.56 Mbps，总测速约 298.61 Mbps）。所以默认值 60 秒是有意的保守值。
- 取值口径：守护进程对 `pool_size` 的校验范围是 **1..24**，但学校侧边界是**同一账号最多 6 个设备/会话**
  同时接入，所以实用区间是 **2..6**，默认 `1`（单会话兼容模式）。（素材差异说明：早期计划书写的是
  “1–6”，实现里放宽到了 1–24，这里以**实现**的校验范围为准。）
- `kmod-macvlan` 缺失或与内核不匹配时，次级会话**不会静默失败**：会话直接标失败并给出“内核未提供
  macvlan”一类明确原因（`dmesg` 里能看到 macvlan 创建错误）。
- 测速是**串行**的：任意时刻最多一条会话在测速，避免多条同时测速把出口抢爆；代价是测速读数可能被
  分流流量分摊压低，这是被接受的误差。
- mwan3 段由本包生成，但本包**不主动** `mwan3 reload`，接口状态变化交给 netifd 事件自然生效。
- `pool_keepalive=0` 时，首轮检测完成后就进 idle，不再做后台维护。
- 回到 `pool_size=1` 就是单会话兼容模式；守护进程会保留主 WAN 的原有行为，不会静默改写 WAN 配置。

## 7. 可选：SNI 分流（zapret）

**用途**：校园网按 SNI（TLS ClientHello 里的域名）做黑名单式限速时，在出口把命中名单的连接首包做
分片/乱序/假包，使 DPI 读不到 SNI，流量落回默认全速类。客户端零配置、不装证书。

**完整部署指南不在本文**，见仓库文档 `docs/reference/SNI-DESYNC.md`（按 OpenWrt 版本与防火墙
后端分路径，含验收与排障）。这里只给部署这条线上的要点。

### 7.1 自动探测模式 + 离线包

【在 Windows / Linux 工作机执行：传文件】

```sh
ssh root@<路由器IP> 'cat > /tmp/zapret-embedded.tar.gz' < CampusRedialWrt/tools/zapret-embedded.tar.gz
ssh root@<路由器IP> 'cat > /tmp/install-sni-desync.sh' < CampusRedialWrt/tools/install-sni-desync.sh
```

【在路由器执行：安装】

```sh
sh /tmp/install-sni-desync.sh --offline=/tmp/zapret-embedded.tar.gz --dry-run   # 先预演
sh /tmp/install-sni-desync.sh --offline=/tmp/zapret-embedded.tar.gz
```

- `--offline=<tarball>`：用本地发行包（**推荐**，仓库内嵌 `CampusRedialWrt/tools/zapret-embedded.tar.gz`）。
  不指定时脚本从 GitHub 下载并依次尝试镜像，全部失败会提示改用 `--offline=`。
- **模式自动探测**：内核 `NFQUEUE` target 与 `/usr/lib/iptables/libxt_NFQUEUE.so` 都在 → 用 **nfqws**
  （透明队列，性能最好）；否则回退 **tpws**（nat DNAT，兼容精简内核）。也可强制
  `--mode=nfqws|tpws`。探测逻辑见脚本 `detect_mode()`。
- 其余参数：`--ip6` 同时处理 IPv6（多拨 PPPoE 通常无 IPv6，默认跳过）、`--dry-run` 只回显。
- 在线文件与解压出的二进制**全部校验 SHA-256**，不匹配立即中止。
- 该脚本只覆盖 **21.02.x (fw3/iptables)**；fw4/nftables（22.03+）请在 `check_requirements` 处直接改走
  上游 `install_easy.sh`，脚本会有明确提示。

### 7.2 hostlist 维护（含一条反直觉的实测语义）

```sh
# 【在路由器执行】
vi /opt/zapret/ipset/zapret-hosts-user.txt     # 每行一个域名，支持后缀匹配（如 .baidu.com）
/etc/init.d/zapret restart                     # 改完名单后重启生效
```

装好 zapret 后，LuCI 页面里也会出现 SNI 分流面板：显示运行状态与模式、实时流量，可直接编辑
hostlist 并保存、启动/停止/重启服务（走 `campus_redial` 的 `zapret_*` RPC）。

> ⚠️ **必须记住的语义（v72.13 实测）**：`zapret-hosts-user.txt` **存在但为空 = 匹配所有主机**，
> 也就是“**空 hostlist 等于对全部域名生效**”，而**不是**“不生效”。日志里该 profile 会标 `(empty)`，
> 不做任何 hostlist 检查就直接命中。所以看到名单是空的，不要以为分流没开。

### 7.3 停止/开启的正确姿势

> ⚠️ **不要把 `/etc/init.d/zapret stop` 当作“关闭分流”**。tpws 模式下 iptables 会把 LAN 出站
> 80/443 **全部** DNAT 到 `127.0.0.127:988`（名单筛选由 tpws 自己做），`stop` 只停进程**不摘跳转**，
> 于是所有网页 connection refused——**LuCI 面板自己也在 80 端口，连管理页都打不开，现象就像路由器死机**。

正确顺序（也是面板按钮做的动作）：

```sh
# 【在路由器执行】关闭分流：touch → stop_fw → stop（先摘跳转再停进程，避免死端口窗口）
touch /var/run/zapret.off
/etc/init.d/zapret stop_fw
/etc/init.d/zapret stop
/etc/init.d/zapret disable        # 可选：让“已停止”跨重启保持

# 开启分流：先起进程再补跳转（避免“有跳转无监听”）
rm -f /var/run/zapret.off
/etc/init.d/zapret enable
/etc/init.d/zapret start
/etc/init.d/zapret start_fw
```

判断故障态看“`running` 与 `redirect` 是否一致”：`!running && redirect` 就是上面那个黑洞。
安装脚本生成的 `/etc/firewall.zapret` 另带两条守卫：服务未启用或有 `/var/run/zapret.off` 时不补跳转；
**访问路由器自身 IP 的 80/443 永不投入 tpws**，所以即使 tpws 崩溃，管理面板仍可达。
验收与 A/B 测速方法论见 `docs/reference/SNI-DESYNC.md` 第七节。

## 8. 升级与卸载

【在路由器执行】

```sh
opkg install /tmp/luci-app-campus-redial_<新版本>.ipk   # 升级
opkg remove luci-app-campus-redial                      # 卸载
```

- **升级**：conffile 全部保留——`/etc/config/campus-redial`、`/etc/campus-redial/stats.json`、
  `last-run.json`、防火墙管理记录（已实测用户自定义 UCI 值不丢失）。prerm 检测到参数为 `upgrade`
  时会直接返回，不做清理；postinst 随后重新 enable 服务。
- **卸载**：prerm 只清理**本包标记过的**内容——`network.wan2..wan24`（仅带
  `campus_redial_managed=1` 的）、`campus_wanN_device`、mwan3 的 `campus_redial_*` 段，以及本包临时改动
  的 IPv6 委派设置。`lan` 与主 `wan` 原样保留（卸载回归实测：`lan` 与 `wan` 的 UCI 哈希前后一致）。
- SNI 分流是独立的一套，用它自己的卸载脚本（幂等，hostlist 会自动备份到 `/tmp`）：

  ```sh
  # 【在路由器执行】
  sh /tmp/uninstall-sni-desync.sh
  ```

## 10. 已知限制

1. **仓库内的历史 apk 产物不适用**：`CampusRedialWrt/dist/luci-app-campus-redial-1.0.0-r1.apk` 是
   OpenWrt 25.12.5 的历史构建产物（`arch:x86_64`），**不能在 21.02.7 上安装**；21.02.7 必须用第 3 节的
   标准 SDK `.ipk` 流程。`CampusRedialWrt/tools/build-dev-apk.sh` 同理，面向 25.12 的 APK/ucode 工具链，
   仅供历史追溯，不要分发。
2. **没有经 21.02.7 验收的现成包**：所有架构都要自己按第 3 节构建，构建需要 Linux 环境。
3. **探针与测速地址是示例值**（斗鱼 CDN、西电测速站）。不改的话，其他学校会出现“不停重拨”或
   “200 Mbps 模式一直失败”——先用 `campus-redialctl test` 看失败原因，再换成本校可达/授权的端点。
4. **多拨的真实环境验收尚未完成**：VM 已验证 `pool_size=2/5` 收敛、60 秒认证间隔、独立 MAC、测速互斥；
   **仍待真实环境复测**的是掉线自动补拨、mwan3 实际分流效果（iperf3 总吞吐 > 单会话）、
   `busy_threshold_kbytes` 大流量挂起。仅生成了 mwan3 配置**不能**算作启用了聚合，必须
   `mwan3 status` + `ip rule` 有运行时证据。
5. **同账号 6 会话上限**：这是学校侧限制，`pool_size` 调再大也不会突破；过密的认证频率会被拒绝，
   所以认证间隔默认 60 秒。
6. **SNI 分流受防火墙后端限制**：本仓库脚本只走 21.02.x 的 fw3/iptables；fw4/nftables 走上游
   `install_easy.sh`。非 armv7 架构需要自行改脚本里的二进制目录与哈希。
7. **本包不提供**绕过认证、伪造凭据、修改白名单等任何能力；也不重启整机网络、不改 LAN/Wi-Fi/LuCI/uhttpd。
