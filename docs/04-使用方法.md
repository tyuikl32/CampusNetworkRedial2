# 使用方法

本文只讲**已经装好之后怎么用**；安装部署见 `docs/02-部署-通用.md` 与
`docs/03-部署-AX3000-自编内核模块.md`。命令块标注 **【Windows】** 或 **【路由器】**，
设备路径写绝对路径，凭据用 `<账号>`、`<密码>`、`<路由器IP>` 占位。

---

## 1. 两条使用路径

| 项目 | Windows 单机拨号 | 路由器全局接管 |
| --- | --- | --- |
| 入口 | `CampusNetworkRedial.csproj`（C#）或 `Redial-UntilCampusReady.ps1` | LuCI「服务 → 校园网自动重拨和集流」 |
| 运行位置 | 每台 Windows 机器各跑一份 | 路由器上跑一份 `campus-rediald` |
| 覆盖范围 | 只影响这台 PC 的拨号连接 | 影响所有走该路由器的设备 |
| 拨号方式 | `rasdial.exe` 断开/连接已有电话簿条目 | netifd/PPPoE，可选多拨连接池（`wan2..wan6`） |
| 独有能力 | 200 Mbps 测速、托盘通知、任务计划自启 | 多拨 + mwan3 分流、SNI 分流面板、累计统计 |
| 适合谁 | 宿舍单机直连校园网、不想动路由器 | 已用路由器拨号的宿舍/实验室，想让全部设备受益 |

两者可以同时存在，但**同一个 PPPoE 账号同时被两边拨号会被 BRAS 拒绝或互相顶掉**，选一条走即可。

## 2. Windows 侧用法

### 2.1 C# 控制台程序

**【Windows】** 需要 .NET 8 SDK，仓库根目录执行：

```powershell
dotnet run --project .\CampusNetworkRedial.csproj -- --help          # 看内置用法
dotnet run --project .\CampusNetworkRedial.csproj -- --test-only --normal-mode
dotnet run --project .\CampusNetworkRedial.csproj -- --dial-name "校园网" --max-attempts 5
dotnet run --project .\CampusNetworkRedial.csproj -- -200MbpsMode --dial-name "校园网"
dotnet run --project .\CampusNetworkRedial.Tests\CampusNetworkRedial.Tests.csproj
```

**模式选择**（不指定模式参数时**默认普通 + 200 Mbps 两者兼具**，两项并行测试，都通过才算好出口）：

| 参数 | 效果 |
| --- | --- |
| 不传模式参数 | 两者兼具（并行） |
| `--normal-mode` | 仅普通模式（多轮连通性探测） |
| `-200MbpsMode`（也接受 `--200MbpsMode`） | 仅 200 Mbps 模式（下载测速超阈值） |
| 两个都传 | 仍是两者兼具 |

**`--test-only`**：只测当前连接、**始终不拨号**。开启普通模式时执行完整三轮连通性确认；
只开 200 Mbps 模式时执行一次下载测速（默认 5 秒窗口）；默认两者兼具时并行执行这两项。
注意两点：单独传 `--test-only` 走的是 `AppOptions` 默认的**两者兼具**，只想确认连通性请写
`--test-only --normal-mode`；`--test-only` **没有测速地址参数**，测速目标固定为
`AppOptions.BandwidthTestUri` 的默认值（西电端点），换学校需改代码或用路由器侧配置。

**自动模式（不带 `--test-only`）流程**：先测一次当前连接（**首轮不主动重拨**）→ 不满足才进入
「断开 → 等 2 秒 → `rasdial` 连接 → 等 `--settle-seconds` → 再测」的循环，最多 `--max-attempts` 次。
成功后直接退出、不读控制台输入，适合放进任务计划程序。

**退出码**：`0` 成功；`1` 达到最大重拨次数 / 测试失败 / 运行异常；`2` 参数错误。

**托盘通知**：结束时报 Balloon——成功用信息提示，失败、达到重拨上限、运行异常用错误提示，
Ctrl+C 取消显示「已停止」；图标数秒后自动清理。

### 2.2 PowerShell 脚本

**【Windows】** 只检测当前出口、不拨号，以及自动重拨直到好出口：

```powershell
powershell -ExecutionPolicy Bypass -File .\Test-CampusExit.ps1
powershell -ExecutionPolicy Bypass -File .\Redial-UntilCampusReady.ps1
powershell -ExecutionPolicy Bypass -File .\Redial-UntilCampusReady.ps1 -DialName "校园网"
powershell -ExecutionPolicy Bypass -File .\Redial-UntilCampusReady.ps1 -DialName "校园网" -200MbpsMode
```

最简单的方式是直接双击 `Redial-UntilCampusReady.bat`（会先自动识别电话簿里的宽带名称）。

- 不传 `-DialName` 时自动识别，识别不到时默认「宽带连接」。
- 200 Mbps 模式每次重拨后测速，结果大于 150 Mbps 立即退出，否则持续断开重拨；速率窗口硬编码
  为 5 秒（脚本内 `cts.CancelAfter(5s)`，不随 `-TimeoutSeconds` 变）。
- `-200MbpsMode` 与 `-TestOnly` 不能同时使用，脚本会直接报错。
- 判定为好出口后打印「好了喵」并询问：输入 `Y` 继续重新探测（失败会自动重拨），其它键退出；
  全程 `Ctrl+C` 可随时停止。

开机自启：双击 `Set-AutoStart.bat`，选 `[1] 开启` / `[2] 关闭`。它写的是
`HKCU\Software\Microsoft\Windows\CurrentVersion\Run`，**登录后**触发，不是开机即跑。

### 2.3 判定逻辑与参数表

- 每轮探测 `ProbeCount` 次，**全部通过**才算这一轮通过。
- 三轮探测（两段间隔确认）都通过才判定为好出口；第 1→2 轮之间等 `ConfirmIntervalSeconds`，
  第 2→3 轮之间等更久的 `ThirdIntervalSeconds`，避免「前两轮通过后出口又变差」被误判。
- 探测只判**可达性**：拿到任何 HTTP 状态码（含 4xx/5xx）都算通过，只有超时或连接异常算失败。
- 200 Mbps 模式判据是「测速**超过**阈值」，即严格大于 `BandwidthThresholdMbps`（默认 150）。

参数表（**Windows 侧**，默认值以代码为准）：

| 参数 | PowerShell 默认 | C# 默认（`AppOptions.cs`） | 说明 |
| --- | --- | --- | --- |
| `-DialName` / `--dial-name` | 自动识别 | 自动识别（`rasphone.pbk`） | 拨号连接名，`rasdial` 可查看 |
| `-TestOnly` / `--test-only` | 关 | 关 | 只测当前网络，不拨号 |
| `-TimeoutSeconds` / `--timeout-seconds` | 4 | 4 | 每次探测超时秒数（1..60） |
| `-ProbeCount` / `--probe-count` | 3 | 3 | 每轮探测次数（1..10） |
| `-SettleSeconds` / `--settle-seconds` | 3 | 3 | 拨号后等待多少秒再探测（0..300） |
| `-ConfirmIntervalSeconds` / `--confirm-interval-seconds` | 12 | 12 | 第 1、2 轮确认之间的间隔秒数 |
| `-ThirdIntervalSeconds` / `--third-interval-seconds` | 30 | 30 | 第 2、3 轮确认之间的间隔秒数 |
| `-PauseSeconds` / `--pause-seconds` | 2 | 2 | 重拨之间的等待秒数（1..600） |
| `-MaxAttempts` / `--max-attempts` | 0（不限次） | 99 | 最大重拨次数；C# 范围 1..99，PowerShell `0` 表示不设上限 |
| `-200MbpsMode` | 关 | 关 | 下载测速，超过 150 Mbps 后停止 |
| `--probe-uri`（仅 C#） | — | 斗鱼 CDN 两个地址 | 普通模式探针，可重复传入覆盖默认值 |
| 测速时长/阈值/地址（仅 C#） | — | 5 秒 / 150 / 西电端点 | **没有对应命令行参数**，改默认值要改 `AppOptions.cs` |

> ⚠️ 仓库根 `README.md` 的参数表写的是 `-SettleSeconds 10`、`-PauseSeconds 8`、`-MaxAttempts 99`，
> 与当前代码不一致。**以代码为准**（`param()` 是 3 / 2 / 0），README 待修。

## 3. 路由器侧用法（LuCI 面板）

**【路由器】** 打开 `http://<路由器IP>/`，左侧菜单 **服务 → 校园网自动重拨和集流**
（`admin/services/campus-redial`；菜单项与页面 `<h1>` 标题都是「校园网自动重拨和集流」）。
同一页面从上到下是：运行状态 → 配置（含多账号连接池）→
**SNI 分流（解除域名限速）** → 最近日志。页面每 2 秒轮询一次状态。

### 3.1 「校园网自动重拨和集流」部分

**状态指标**（「运行状态」表）：

| 指标 | 含义 |
| --- | --- |
| 进程 | 状态机总状态：空闲 / 后台未启动 / 正在启动 / 等待网络 / 正在拨号 / 正在检测 / 正在重拨 / 成功 / 失败 / 已停止 / 错误 / 在线 / 离线 / 流量繁忙（检测已挂起） |
| 过点模式 | 普通（三轮连通性）检测结果：未启用 / 等待 / 检测中 / 成功 / 失败 / 未知 |
| 高宽模式 | 200 Mbps 测速结果 + 最近一次实测 `speed_mbps` |
| 连接池状态（连接/检测） | 「已连接 N / pool_size；检测通过 M / pool_size」；已连接但尚未通过检测的会话仍可参与分流 |
| 最后错误 / 更新时间 | 最近一次失败原因（无错时显示「无」）、状态文件写入时间 |

**按钮**（同一行，可用条件写在括号里）：

| 按钮 | 作用（可用条件） |
| --- | --- |
| 启动 | 启动自动重拨状态机（未运行时可用） |
| 停止 | 请求停止当前任务，等待/探测/测速/拨号都会被取消（运行中可用） |
| 测试当前出口 | 只测当前在线出口，**不拨号**（未运行时可用） |
| 立即重拨一次 | 立即断开重拨一轮并测试（未运行时可用） |
| 清空统计 | 清空累计统计 `/etc/campus-redial/stats.json`（始终可用） |

**连接池会话表**：每行一条 PPPoE 会话，列为 会话、认证账号、状态、拨号连接（未连接/拨号中/
已连接）、检测状态（待检测/检测中/等待检测/检测通过/检测未通过）、过点模式、高宽、测速、
实时流量/连接（下行、上行、连接数）、累计流量（收/发）、会话统计（拨号/重拨、成功/失败、
过点/高宽通过）、错误。`pool_size=1` 时只有一行；没有会话时显示「后台尚未建立会话」。

**配置项与建议值**（配置区，即 `/etc/config/campus-redial`）：

| 配置项 | 默认 | 含义与建议 |
| --- | --- | --- |
| 开机自动运行 | 关 | 写入 `enabled`；开启后 procd 开机拉起守护进程（装包时 postinst 已 enable，不想自动拨号就在这里关） |
| PPPoE 逻辑接口 / 下层设备 | `wan` / 空 | 逻辑接口必须是 PPPoE 协议且本包不会替你创建；下层设备留空时读 `network.wan.device` |
| 校园网账号 / 密码 | 必填 | 填 `<账号>`、`<密码>`；密码只写 `/etc/config/campus-redial`（0600），不会出现在状态 RPC 或日志里 |
| 旧版单账号会话数 / 持续维护连接池 | `1` / 开 | `pool_size` 范围 1..24，多账号配置存在时被忽略；`pool_keepalive` 负责掉线后自动补拨 |
| 认证最小间隔（秒） | `60` | **多拨务必 60**。实测 5 秒间隔只能收敛 2/5，60 秒 5/5 |
| 大流量挂起阈值（KB/s） | `0` | 会话出口秒级流量超过该值就推迟检测；`0` 表示关闭该保护 |
| 过点模式 / 高宽模式 | 都开 | 两个都开时必须都通过才算好出口 |
| 过点模式探针 / 超时 / 每轮次数 | 斗鱼 CDN 两个地址 / `4` 秒 / `3` | 探针可增删多行、必须是 `http(s)://` 开头；每轮全部通过才算本轮通过 |
| 第一轮 / 第三轮确认间隔（秒） | `12` / `30` | 第 1、2 轮之间与第 2、3 轮之间 |
| 测速地址 / 时长 / 阈值 | 西电端点 / `5` 秒 / `150` | **其他学校务必换成自己可达的** LibreSpeed 兼容 `garbage.php`；严格大于阈值才通过 |
| 拨号稳定等待 / 失败暂停（秒） | `10` / `2` | 拨号后等多久再检测、两次尝试之间的等待 |
| 最大拨号次数 | `99` | 达到上限应停在「失败」而不是无限重试 |
| 多账号连接池（表） | — | 每条 `config account`：启用、显示名称、PPPoE 账号/密码、最大连接数（1..24）。有启用账号时连接池大小 = 各账号 `max_connections` 之和 |

### 3.2 「SNI 分流（解除域名限速）」区域

对名单内域名的 HTTPS 连接做 ClientHello 分片，让校园网 DPI 读不到 SNI，流量回到默认不限速类。
当前实机（Redmi AX3000，OpenWrt 21.02.7）跑在 **nfqws 模式**。

**状态指标**：

| 指标 | 含义 |
| --- | --- |
| 服务状态徽标 | 运行中 / 运行中（未接管流量，点**重启**）/ 已停止（直连）/ 未安装 / **异常：跳转残留**（进程没了但 nat 跳转还在，所有网页会 connection refused，连本面板都打不开；点**停止**可立刻摘除跳转恢复直连） |
| 模式 / 开机自启 | `tpws（用户态透明代理）` 或 `nfqws（内核队列）`，由 `/opt/zapret/config` 的 `TPWS_ENABLE`/`NFQWS_ENABLE` 判定；开机自启看 `/etc/rc.d/S21zapret` 是否存在 |
| 流量接管 / DNAT 命中 | `nat` 里是否仍把 LAN 80/443 DNAT 到 `127.0.0.127:988`，以及该跳转规则的包/字节计数（**nfqws 模式下计数为 0 属正常**，它走 mangle NFQUEUE） |
| 名单域名数 | `/opt/zapret/ipset/zapret-hosts-user.txt` 的有效行数 |

**按钮**：

| 按钮 | 作用 |
| --- | --- |
| 启动 | 清停止标记 → `zapret start` → `zapret start_fw`（先起进程再补跳转） |
| 停止 | 打停止标记 → `zapret stop_fw`（先摘跳转）→ `zapret stop`（再停进程）。**仅运行时停止，不 disable 服务，重启后自动恢复开启** |
| 重启服务 | 清停止标记 → `zapret restart` → `zapret restart_fw` |
| 保存名单并生效 | 写 hostlist，然后**自动执行一次「重启服务」**（只改文件不重启进程不生效） |

**域名名单编辑框**（8 行文本框，每行一个域名，`#` 开头为注释，只允许字母数字点连字符和 `*`）：
后缀形式写 `example.com` 即可覆盖其子域，填非法行会报「非法域名行」并整体不保存。

- **⚠️ `hostlist` 文件存在但为空 = 对全部域名做 desync**（实测 zapret v72.13，日志里 profile 标
  `(empty)`，不做任何 hostlist check 就直接命中）。所以「名单是空的」不等于「没生效」，
  而是**全量分流**——本机就是故意留空的用法。
- 想只分流部分域名就逐行写出来；**清空保存等于全量分流，不是暂停分流**，要真正暂停请用「停止」按钮。

**⚠️ 关闭 SNI 分流的正确姿势**：不要只跑 `/etc/init.d/zapret stop`。tpws 模式下 iptables 会把
LAN 的**全部** 80/443 DNAT 到 `127.0.0.127:988`，`stop` 只停守护进程、不摘跳转，于是所有网页
connection refused，连 LuCI 面板都打不开，看起来像死机。必须「先摘跳转、再停进程」（面板
「停止」按钮做的就是这件事）。完整顺序与故障态判据见 `docs/reference/SNI-DESYNC.md`。

## 4. 命令行用法（无 LuCI 时）

**【路由器】** 服务生命周期、状态机控制、RPC 与 SNI 模式切换：

```sh
# 服务生命周期
/etc/init.d/campus-redial status|start|stop|enable|disable

# 状态机控制（写 /var/run/campus-redial/control，守护进程没跑时会自动先拉起服务）
# 子命令只有这 5 个，传别的会打印 "invalid command" 并以退出码 2 结束
/usr/sbin/campus-redialctl start          # 启动自动重拨状态机
/usr/sbin/campus-redialctl stop           # 取消当前任务（等待/探测/测速/拨号都会被取消）
/usr/sbin/campus-redialctl test           # 只测当前在线出口，不拨号
/usr/sbin/campus-redialctl redial_once    # 立即断开重拨一轮并测试
/usr/sbin/campus-redialctl clear_stats    # 清空累计统计

# ubus RPC（对象 campus_redial，rpcd 插件 /usr/libexec/rpcd/campus_redial）
ubus call campus_redial status | start | stop | test | redial_once | clear_stats
ubus call campus_redial logs '{"lines":100}'          # 最近日志，lines 范围 1..200，默认 80
ubus call campus_redial zapret_status                 # SNI 分流状态
ubus call campus_redial zapret_hostlist_get           # 读名单（每行一个域名的字符串）
ubus call campus_redial zapret_hostlist_set '{"hostlist":"example.com\n# 注释\n"}'   # 写名单并自动重启服务
ubus call campus_redial zapret_service '{"action":"stop"}'   # action 只能是 start / stop / restart

# SNI 分流模式切换（**脚本要先推到设备 /tmp 再执行**）
sh /tmp/cr-nfq-switch.sh status   # 看当前模式、跳转、NFQUEUE 规则、连通性
sh /tmp/cr-nfq-switch.sh on       # tpws -> nfqws，需要 /tmp/nfnetlink_queue.ko 且两个模块已加载
sh /tmp/cr-nfq-switch.sh off      # nfqws -> tpws（从 /opt/zapret/config.tpws.bak 还原）
```

`status` 会把 `stats.json` 和 `last-run.json` 拼进结果；`start/stop/test/redial_once/clear_stats`
成功返回 `{"result":true}`，守护进程未运行时返回 `{"error":"后台服务未运行"}`。
`on` 的前置检查：缺 `/tmp/nfnetlink_queue.ko`、`nfnetlink_queue`/`xt_NFQUEUE` 未加载、内核无
NFQUEUE target，或 `/opt/zapret/nfq/nfqws` 缺失，都会直接 `FATAL` 退出而不改配置；脚本仓库副本在
`CampusRedialWrt/kmod-build/remote/cr-nfq-switch.sh`。不通过它时，等价的手工姿势是：

```sh
# 关闭 SNI 分流（顺序不能换）
touch /var/run/zapret.off
/etc/init.d/zapret stop_fw
/etc/init.d/zapret stop
iptables -t nat -S | grep -F -- '--to-destination 127.0.0.127:988'   # 必须为空

# 开启
rm -f /var/run/zapret.off
/etc/init.d/zapret start
/etc/init.d/zapret start_fw
```

`/var/run` 是 tmpfs，停止标记随重启失效——所以「停止」只作用于本次运行，重启后自动恢复为开启；
想让「已停止」跨重启保持，再补一条 `/etc/init.d/zapret disable`。

## 5. 状态与数据文件

| 路径 | 内容 / 什么时候看它 |
| --- | --- |
| `/var/run/campus-redial/status.json` | 当前状态：`state`、`sessions` 数组、各模式结果、`speed_mbps`、计数；页面显示不对或想知道状态机卡在哪一步时看 |
| `/var/run/campus-redial/session.<name>` | 每条会话的 key=value 状态；某一路会话单独异常时看 |

| `/etc/campus-redial/last-run.json` | 最近一次任务结果（含真实测速值）；对应面板「最近一次任务」的测速卡片 |
| `/etc/config/campus-redial` | UCI 配置（0600，含账号密码）；核对配置是否落盘，别 `cat` 到别人能看到的地方 |
| `/opt/zapret/config` | zapret 模式与 desync 参数（`NFQWS_ENABLE`/`TPWS_ENABLE`/`MODE_FILTER`/`OPENWRT_WAN4`） |

## 6. 典型操作剧本

**A. 我要换成多拨并验证叠加**

1. **【路由器】** 把「旧版单账号会话数」改成 2..6，或到「多账号连接池」表里加账号；把
   「认证最小间隔」设为 `60`（默认就是 60，别调到 5）。
2. 保存 → 点「启动」，等「连接池状态」变成「已连接 4 / 4」，「连接池会话」表每行都要
   「已连接 + 检测通过」。
3. 验叠加：`mwan3 status` 看策略，再用 `iperf3` 比对总吞吐是否大于单会话
   （实测数字见 `memory/2026-09-11-ax3000-multidial-live.md`）。
4. 只有主会话在线 → 查 `kmod-macvlan` 是否与内核匹配：`lsmod | grep macvlan`。

**B. 某站又被限速了 / 想让 SNI 分流只管某几个域名**

1. **【路由器】** 在「SNI 分流」区的域名名单里逐行写被限速的域名后缀（如 `example.com`），
   点「保存名单并生效」——它会自动重启服务，只改文件不重启不生效。
2. 验证：「名单域名数」应等于你写的行数；「服务状态」应为「运行中」+「流量接管：是」。
3. 想恢复全量分流：**清空**名单再保存（空 = 对全部域名 desync）。

**C. 我要临时关掉 SNI 分流（做 A/B 对比或某站必须直连）**

1. **【路由器】** 面板点「停止」（先摘 nat 跳转、再停进程，流量立刻直连），或命令行按第 4 节
   顺序手敲；**绝不要只跑 `/etc/init.d/zapret stop`**。
2. 收尾自检：`iptables -t nat -S | grep -F -- '--to-destination 127.0.0.127:988'` 必须无输出。
3. 恢复：点「启动」（或 `start` + `start_fw`）；重启路由器也能恢复。

**D. 我要看为什么一直在重拨**

1. **【路由器】** 看「最后错误」和「最近日志」（或 `logread | grep -i campus`、
   `tail -50 /var/log/campus-redial.log`）。
2. 点「测试当前出口」——失败说明探针在你网络里不可达，先换探针地址；再点「立即重拨一次」
   看一轮完整流程卡在哪一步。
3. 看 `/var/run/campus-redial/status.json` 的 `state`：长期 `waiting_network` 是 WAN 没起来，
   反复 `dialing` 是认证被拒（查账号/物理设备/认证频率）。
4. 若达到「最大拨号次数」仍显示不断重试，那是状态机 bug，不是配置问题；更多排查见
   `docs/05-故障排查.md`。

**E. 我只想确认当前出口好不好（不动任何东西）**

- **【Windows】** `dotnet run --project .\CampusNetworkRedial.csproj -- --test-only --normal-mode`，
  或 `powershell -ExecutionPolicy Bypass -File .\Test-CampusExit.ps1`。
- **【路由器】** 面板点「测试当前出口」，或 `ubus call campus_redial test` / `campus-redialctl test`；
  两者都**不会拨号**。

## 7. 使用中的注意事项

1. **探针与测速地址必须换成自己可达的**：默认的斗鱼 CDN 探针、西电测速端点是示例地址，只用
   明确获授权的健康检查地址；换学校后 200 Mbps 模式会一直失败。
2. **多拨认证间隔用 60 秒**，且**同一个账号别让 Windows 侧和路由器侧同时拨**：前者 5 秒间隔
   实测只能收敛 2/5，两者都会触发 BRAS 拒绝或互相顶掉。
3. **关闭 SNI 分流不要用 `/etc/init.d/zapret stop`**（会留下死端口跳转，整网 80/443
   connection refused，面板也打不开）：用面板「停止」或 `stop_fw` + `stop`；要暂停分流请停服务。
4. **hostlist 留空 = 全量 desync**，不是「没生效」也不是「暂停」。
5. **探针只判可达性**（4xx/5xx 也算通过），要选一个「坏出口必然超时」的端点才有区分度。
6. **密码会留在 shell history**：命令行 `uci set` 写密码后记得 `history -c`，能进 LuCI 就用页面。
7. 面板「启动/测试当前出口/立即重拨一次」在运行中都会置灰，先「停止」再操作。
8. **手工覆盖到设备的文件不登记在 opkg 数据库**，升级/卸载不会管理它们；推送的 shell 脚本必须
   是 LF 换行，Windows 的 CRLF 会让脚本直接语法报错。

以上任一条出问题，先看 `docs/05-故障排查.md`。

## 8. 待确认

1. 仓库根 `README.md` 的参数表与 `Redial-UntilCampusReady.ps1` / `AppOptions.cs` 的默认值不一致
   （`-SettleSeconds` 10 vs 3、`-PauseSeconds` 8 vs 2、`-MaxAttempts` 99 vs 0/99），
   本文按代码写并在 2.3 节注明了冲突。
2. 无 LuCI 时 SNI 分流的命令行替代：`cr-nfq-switch.sh` 只提供 `status|on|off`（模式切换），
   「关闭分流但不换模式」只有「面板停止按钮」与第 4 节那组 `touch` + `stop_fw` + `stop` 命令
   两条路径；仓库内没有单独的 SNI 启停命令行工具，故未杜撰。
3. `--test-only` 的口径：`RedialCoordinator.RunTestOnlyAsync` 把 `fullNormalConfirmation`
   传成 `_options.NormalMode`，因此不显式加 `--normal-mode` 时它按默认的"两者兼具"跑
   （并行测速 + 三轮确认）；且该模式**没有**测速地址参数，`BandwidthTestUri` 只能改代码。
   本文按实现写，旧 README 的"普通模式执行完整三轮"说法已作废。
